# Research Hypotheses Registry

Every hypothesis must be falsifiable, tied to specific live metrics, and tested against a controlled baseline before any architectural claim is made.

| ID | Phase | Statement | Primary Metric(s) | Falsification / Refutation Criterion | Status |
| :--- | :---: | :--- | :--- | :--- | :---: |
| **H0 (Baseline Sanity)** | Phase 3 | Even *without* AI inference, an OpenFlow 1.3 `os-ken` reactive L2/L3 switch exhibits a measurable `Packet-In` saturation knee where p95/p99 handler latency, event-loop lag, and software flow-table occupancy rise nonlinearly as spoofed table-miss rate increases. | `packet_in_latency_p95_ms`, `packet_in_latency_p99_ms`, `event_loop_lag_p95_ms`, `controller_cpu_pct`, `benign_iperf_mbps` | If `os-ken` handles all tested rates up to traffic-generator ceiling with flat latency (<2 ms p99) and <50% CPU, either generator rate is too low or switch datapath saturates before the controller. | `UNTESTED` |
| **H1 (Bottleneck Attribution)** | Phase 4 | Inside a live Python SDN controller, synchronous multi-feature extraction (especially per-packet statistical features mimicking `CICFlowMeter`) and event-loop blocking contribute equal or greater tail-latency degradation than lightweight tree/linear inference alone. | Component breakdown (`extract_ms` vs `infer_ms` vs `flowmod_ms` vs `queue_wait_ms`), `event_loop_lag_p99_ms` | If model inference alone accounts for >80% of latency while feature extraction is negligible (<10%), feature-pruning hypotheses must be revised toward model/runtime optimization. | `UNTESTED` |
| **H2 (Offline-to-Live Gap)** | Phase 4 | Models achieving nearly indistinguishable offline Macro F1 on leakage-free `InSDN`/`CIC-DDoS2019` splits exhibit large differences (>5x) in live p99 latency, controller CPU saturation point, and benign user throughput under flood conditions. | Offline Macro F1 & FPR vs. Live max sustainable `Packet-In`/s at p99 < 10 ms and benign QoS retention % | If heavy models impose negligible live overhead (<10% CPU delta, <1 ms p99 delta) under realistic loads, the bottleneck thesis is weakened. | `UNTESTED` |
| **H3 (Targeted Mitigation — TBD after Phase 4)** | Phase 5 | *Deferred until H1 localizes the true bottleneck.* Candidate interventions (native OpenFlow feature subset, decoupled async/batched inference, two-stage threshold+AI gatekeeper, selective rule installation) will be formulated as separate sub-hypotheses (`H3a`, `H3b`, `H3c`) changing one variable at a time. | Primary metric to be locked before Phase 6 comparative evaluation (e.g., p99 `Packet-In` latency & benign throughput at matched F1 / FPR < 1%) | Fails if improvement is within noise / 95% CI overlap across repeated seeds or degrades Macro F1 / FPR unacceptably. | `DEFERRED` |
